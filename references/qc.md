# 自检

## 自动（`build.py` → `out/build_report.txt`，`qc.py` → `out/qc.txt`）

1. 卡拍事件的实际帧与目标拍点偏差 ≤ 1 帧（画面不晚于声音）
2. 字幕停留满足公式；中文 ≤ 22 字；不重叠、间隔够
3. 转场不过长；pan 的两个镜头不一样；同一时刻的音效不扎堆；限幅压得不多
4. 成片 1920×1080、30fps、h264 + aac、时长 = BGM（±1 帧）、true peak ≤ -1 dBFS

`[FAIL]` 必须修；`[warn]` 也都要处理，留着的在交付说明里写清楚为什么。

## 人工（必须打开图看）

预览：`python tools/preview.py --scenes`（每场一帧），然后**专门抽这些帧**：
- 每个转场的中间（pan / zoom / wipe 一半的位置）：两个场景叠在一起时有没有错位、重影、露出黑底
- 每个主事件前后 2–3 帧（盖章、闪白、落地）
- 每个场景的第一帧和最后一帧
- 字幕出现的帧（和画面元素撞没撞）

逐张检查：

- [ ] **和别的片子像不像**：开场 / 标题 / 揭晓 / 反转 / 结尾 / 转场方式，有没有在复用示例片或以前的片子
- [ ] **主体够不够大**：有没有小图标居中、四周大片空黑的画面
- [ ] **层次**：有没有只有一层的画面
- [ ] **动**：连续几帧有没有完全不动的
- [ ] 文字有没有出画、被裁、叠在别的东西上；同一个标签有没有出现两次
- [ ] 75% 高度以下有没有被画面压住；亮的画面上字幕能不能看清（不行就加底部暗渐变）
- [ ] 每屏强调色 ≤ 2 种；全彩只在反转
- [ ] 中文是不是细宋体（不是黑体 / 微软雅黑）
- [ ] 世界里的线 / 箭头有没有横穿卡片或文字
- [ ] 静态缩略图和场景动态版本交接时，有没有两份叠在一起

## debug.mp4

右上角：帧号、最近拍点（±几帧）、当前场景、最近的 cue（刚触发时变黄）；拍点处闪圆点，downbeat 是大红点。拖着看：每个视觉动作都应该和圆点同时出现。

## 常见问题

| 现象 | 原因 / 修法 |
|---|---|
| 中文变成黑体 | 文字写死在 tsx 里没进 storyboard → 挪到 props |
| `No scene component "X"` / `has no event "y"` | 没注册 / storyboard 里没写这个事件（或用 `at("y", 秒)` 给默认值） |
| 角落标签跟着镜头飘走、出画 | 用 `<Meta>` 或 `<Hud>` 包起来 |
| pan 期间画面变黑 | World 的可见度要按"份额"算（pan 线性交接），不要用场景内容的不透明度 |
| 渲染报 Chrome out of memory | `python tools/render.py --concurrency 2`；减少大面积 blur / drop-shadow、上千个 DOM 元素（改用 canvas） |
| 首次渲染卡在下载 Chrome | 网络问题；设 `VKV_BROWSER_FROM=<另一个 Remotion 项目>` 后重跑 new_project |
| 卡点"感觉"不对，但报告全过 | 事件挂错了拍：用 debug.mp4 找到那一帧，改 `at` / `snap` |
| 音效太响 / 太轻 / 听不见 | 单个改 `gain`，整体改 `meta.sfxGain`；在鼓很密的段落用短促的真实拟音（knock / click / stamp），柔和的合成音会被盖住 |
| 改了 skill 的引擎，项目里没生效 | `python <skill>/scripts/new_project.py <项目>` 刷新 tools 和 lib / components / Video.tsx（不动你的场景） |
